# 候选人数据与 PII 生命周期

HireFlow 处理候选人姓名、邮箱、电话、简历信息、Offer 和邮件正文。这些数据属于敏感招聘数据。本页描述项目应遵循的边界；当前仓库尚未把所有保留期和匿名化任务实现为生产定时作业，因此不能把本页当作已经上线的合规承诺。

## 数据分类

| 类型 | 示例 | 处理原则 |
| --- | --- | --- |
| 账户凭据 | 密码哈希、Refresh Token 哈希、JWT Key | 不记录明文；密钥由环境或密钥管理系统注入。 |
| 候选人 PII | 姓名、邮箱、电话、简历 | 仅租户授权用户可访问；导出、日志和测试数据必须脱敏。 |
| 招聘决策 | 评分卡、Offer、阶段审计 | 限定用途，设置业务和法务保留期，超期删除或匿名化。 |
| 通知内容 | 邮件地址、主题、正文、退信原因 | 只为投递和审计保留，禁止写入指标标签。 |

## 删除与匿名化流程

1. 由租户管理员发起候选人删除请求，并记录操作者、范围和请求时间。
2. 在事务中阻止新的申请/排期，删除不需要保留的可用时段、通知正文和邮件投递内容。
3. 对依法或业务必须保留的审计记录使用不可逆匿名标识替换姓名、邮箱和电话，保留状态变化而不保留身份信息。
4. Outbox/Inbox 只保留排障所需字段；payload 中的 PII 应随主体匿名化，或在短保留期后整体清除。
5. 删除任务必须幂等，并产生不包含原始 PII 的执行审计。

## 建议保留策略

- 未录用候选人资料：由租户配置保留期，默认建议 180 天后提醒删除或匿名化。
- Offer、评分卡和招聘审计：依据企业法务要求配置，不能无限期默认保留。
- 已发布 Outbox、已处理 Inbox：短期在线保留用于排障，之后归档或删除。
- 邮件正文和失败详情：成功投递后缩短保留期；错误栈必须经过截断与脱敏。
- 指标：只保留聚合数量和延迟，不使用邮箱、候选人 ID、JWT 或正文作为 label。

## 备份中的删除

在线删除不能立即改写历史备份。备份应加密、限制访问并设置自动过期；恢复旧备份后必须重新执行删除/匿名化账本，再允许环境对外提供服务。生产演练需要验证“恢复成功”和“被删除主体不会重新出现”两个条件。

## 日志和可观测性

- 禁止记录 Authorization、Cookie、密码、Refresh Token、JWT 完整值和邮件正文。
- 邮箱只允许掩码展示；错误日志使用事件 ID、请求 ID 和内部记录 ID 关联。
- Prometheus label 必须保持低基数，不包含租户名称、邮箱、候选人姓名或消息正文。
- 故障样本应标记来源和生命周期，避免 Demo 将历史失败记录误认为当前系统故障。
